# External-memory retrieval and judgment: five perspectives

Baseline: `ccae16ef2700ba34784a46413b7033a1672a8ee7` (PR #165).
Nine new initial no-history readers, one reused prior observation, eleven
pattern views. Two targeted, single rechecks follow the completed initial group.
This is an evaluation of existing memory routes, not five storage types or a
new evaluation harness. It does not add FN125 real-use executions.

## Evidence and protocol

The [matrix](matrix.md) and [cases](cases.json) were frozen before new readers.
Their original hashes, snapshot preparation, actual dispatch hashes and
post-read integrity checks are in [setup](setup.json). `initial_status` in the
frozen case file is the pre-run state, not the final result.
[Read receipts and actual judgments](reads.json) separate model-visible source
sections from whole-blob or search I/O. [Assessments](results.json) separate
judgment, required acquisition, selectivity and claim limits.

Each reader received only the normal AGENTS entrance, the case situation and
read-only scope in an independent clone. Expected answers, expected lower paths,
the evaluator matrix, sibling answers and new trial artifacts were absent.
Each session used `fork_turns: none`; no alternate model was introduced.
The first nine snapshots were clean at the fixed baseline before and after.
Files were read-only, but this was not an OS security isolation or access-audit
experiment: the agents shared a host, tool availability and model family.

No mid-trial hints or human intervention occurred. After m01–m03 had issued
their final judgments, each received one request to consolidate already-reported
receipts; they reported no new read or judgment. This documentation intervention
is recorded rather than represented as a completely message-free trial.

PR #165 is reused only for the same Run 3 later-outcome condition. Its AGENTS,
card, procedure, original observation and restart point qualify as described in
the matrix. No second reader or additional real-use success is credited.

## What changed a judgment

- **V214 actual use (m01):** recorded remote/main pair, ancestry and clean-worktree
  checks made continuation admissible within current authority. The same record
  preserved broad-search/old-handoff overhead. The reader therefore supported
  bounded maintenance, not a general time/cost saving or needless revision.
- **Historical FN125 comparison (m03):** persisted Bundle evidence sufficed in
  Case 1, receiving-context-only judgment required added identity in Case 2,
  and missing Bundle stopped the affected change until verified arrival in
  Case 3A. Case 3B also showed an already-repaired unnecessary path-based BLOCK.
  Original external records were unavailable; the underlying evaluation data
  was synthetic-only. m03 read that boundary but did not restate it explicitly.
- **FN141 incident (m05):** three failed Actions runs with zero jobs, unchanged
  retrigger and identical workflow recreation were followed by success through
  a different direct-write route. That distinction prevented erasing failed-method
  evidence. Unknown cause/private originals remained unknown, and Candidate
  status was not promoted to Canon.
- **Run 3 later result (r165):** PR #165's reader used the later placement repair
  to exclude duplicate repair while preserving the earlier unrepaired finding
  and unresolved external transport. Its original receipts remain the evidence.
- **Transfer Packet pause (m08):** FN059/060 show internal readiness without a
  real input contract or demonstrated transfer benefit; FN057 supplies the
  missing size, purpose, authority, no-touch, acceptance and recovery inputs.
  Current AGENTS/Folded status prevented inherited CAP authority. A partial new
  task permitted reconsideration, not automatic packet creation or permanent ban.

Upper controls also showed useful non-acquisition: m02 did not revisit practice
history, m06 did not inspect the external incident, m07 did not inspect a later
outcome, and m09 did not reread old Note bodies. m04 located the missing condition
without inventing normality. These controls are not real production executions.

## Retrieval failure, minimal repair and one recheck

m05 and m08 treated the current upstream restart route as a general history
index. In m05, a superficially related later-success story led through Run 3,
O69, MISTAKEN and FN125 before a topic search found the actual incident. m08
loaded the entire unrelated causal trajectory before finding the pause records.
The eventual correct answers do not make these detours useful acquisition.

The only operating edit is ten added AGENTS lines: the upstream restart point
is not a general history index; for another historical event, use bounded
topic/filename discovery, relevant sections and named evidence, preserve event
identity and stop with the evidence limits. It contains no case answer or FN141/
Transfer Packet path. The existing current card, Canon, ledger, lifecycle and
real-use/delayed-outcome observations are unchanged.

Only m05 and m08 exercise the repaired event-routing failure. Their fresh
rechecks use identical candidate trees based on the frozen main plus **only**
the AGENTS edit. Local candidate commits are not published main or fetchable canonical commits;
their tree is reproducible from the baseline plus the recorded AGENTS bytes.
Provenance is explicit in the neutral prompts. Evaluator artifacts and later summary/current
blocks are absent. There is one recheck per affected case and no retry-until-pass.

Both one-shot rechecks acquired the required event and reached the bounded
decision, with no unrelated delayed-outcome/Run3/O69 descent. m05 found FN141
by searching `field_notes`, then consulted relevant Gate/rechallenge references.
m08 found the Transfer Packet family by topic search, recovered pause and input
conditions, and did not transplant a prior medium-task CAP. See the
[recheck receipts](recheck_reads.json) for exact ranges, reasons and limitations.
Source text displayed was 46,217 characters for m05 and 57,054 for m08, with
search stdout separate. Both still read substantive relevant evidence; m08's
small overlapping ranges are counted twice as actually displayed. These two
observations support the repaired route in these cases, not measured savings
or general retrieval reliability. Initial failures remain in the table above.

The patch-only rechecks do not test the later evaluation summary/current-state
blocks added for delivery. The initial upper controls are not rerun or counted
again, and no claim of behavior on every future history query is made.

## Limits and next re-evaluation condition

The bounded discovery found no publicly reproducible counterexample to a
registered FN125 version. FN141 is a real public incident summary and unresolved
cause experience; its private raw provenance and root cause are not reproduced.
Synthetic controls, historical record review and PR #165 reuse remain separate.
The one real execution already in the FN125 ledger remains one execution.

Residual over-reading in m01/m03/m04 and m03's source-class reporting omission
are recorded. Their required routes and decision conditions already worked;
the source itself places its synthetic boundary beside the result. This does
not justify another instruction or retry merely to obtain a clean score.
Revisit if such omissions change a real decision, repeat in a new authorized
case, or new source/counterevidence makes the current rule or boundary inadequate.

There is no automatic monitoring, new harness, model, Companion expansion,
whole-history migration, release, tag or outreach. Another trial requires a
new concrete question or evidence and current authority.
