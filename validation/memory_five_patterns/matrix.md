## Protocol and assessment

Each new case gets one `fork_turns: none` session and its own clean, read-only
repository copy. The normal entrance and the situation are provided; this
matrix, expected decisions, lower evidence paths and sibling answers are not.
Readers report files/ranges, why they descended, displayed text versus machine
I/O, missing facts and actual judgment. No additional hints are planned.

Record judgment and retrieval separately. A safe/correct answer without required
experience acquisition is **not confirmed memory use**. Upper-only cases can
have correct judgment but fail selectivity if they reload histories without a
decision-relevant reason. Do not infer quality from file count alone or treat
mandatory current instructions and hash I/O as semantic history consumption.
Unmeasured input/token/time/cost/burden remains unknown.

Complete the initial group before any entry/condition repair. Consolidate only
necessary fixes; recheck each affected case in a separate fresh session **once**.
Preserve first failures and remaining failures. No automatic loop, new harness,
model, Companion work, bulk migration or count-based promotion is introduced.
Unsafe unresolved authority/decision defects block merging the affected operating
change; correct limitation reporting is preferable to manufacturing all-PASS.
